# Campus SkillSwap 中文逐步学习指南

## 1. 项目是怎么创建的

本项目直接使用 Python 和 Django，可在 VS Code 中编辑和调试，没有额外的前端构建工具。安装并激活虚拟环境后，初始搭建命令如下（已有项目不要重复执行）：

```bash
django-admin startproject campus_skillswap .
python manage.py startapp skills
```

`campus_skillswap` 管全站配置，`skills` 管市场业务。`settings.py` 的 `INSTALLED_APPS` 加入 `skills`；`TEMPLATES` 指向根目录 `templates`；静态目录指向 `static`。数据库采用 Django 自带的 SQLite 配置，不需要单独安装数据库服务器。

请求的基本流程是：浏览器 URL → `campus_skillswap/urls.py` → `skills/urls.py` → `skills/views.py` → 模型查询／表单验证 → HTML 模板 → 浏览器。

## 2. 数据模型

打开 `skills/models.py`。

`Skill` 表示一个技能帖：`owner` 关联 Django 用户；`title` 是标题；`category` 使用固定分类选项；`description` 说明服务；`exchange` 填写费用或希望交换的技能；`location` 填写校园位置或 online；两个日期字段记录创建与修改时间。

`ForeignKey` 表示一个用户可以拥有多个技能帖，`related_name='skills'` 允许通过 `user.skills.all()` 查询其帖子。`on_delete=CASCADE` 表示删除用户会删除其帖，删除技能会删除关联评价。`get_absolute_url()` 返回技能详情地址。

`Review` 关联技能和评价人。评分限制为 1–5，评论必填，最多 2000 字符。`UniqueConstraint` 从数据库层面禁止同一人对同一帖存多条评价；`CheckConstraint` 从数据库层面限制评分范围。`clean()` 禁止自评，表单验证会调用它；Django 的普通 `save()` 不会自动调用 `full_clean()`，以后编写脚本或新入口时也需要调用验证并保持权限规则。

修改模型后运行：

```bash
python manage.py makemigrations
python manage.py migrate
```

第一条生成数据库变更文件，第二条执行变更。迁移文件应提交 Git，个人开发数据库不应提交。

## 3. 表单

打开 `skills/forms.py`。

`RegisterForm` 继承 `UserCreationForm`，保留用户名、密码确认及密码验证；不手工保存明文密码。`LoginForm` 继承 `AuthenticationForm`。`SkillForm` 和 `ReviewForm` 继承 `ModelForm`，根据模型生成输入并检查数据。

`SkillForm.Meta.fields` 只列出允许学生编辑的内容，不包含 `owner`。帖主由服务器设置，避免用户伪造表单来改变所有者。评价同样不允许浏览器指定作者和技能。

`style_fields()` 给普通输入添加 `form-control`，下拉框添加 `form-select`。模板 `includes/form_fields.html` 统一显示标签、帮助文字和每个字段的错误。无效提交保留用户输入，方便修改。

## 4. 注册、登录和退出

`register()`：GET 展示空表单；POST 验证并保存用户，随后登录并跳转 dashboard。`login_view()` 使用认证表单验证凭据；登录后可返回之前想访问的本地页面。`next` 地址经过主机校验，避免跳转到外部恶意站点。

`logout_view()` 只接受 POST。导航栏中的退出按钮实际是带 CSRF token 的表单。不要把退出、删除等变更操作写成普通 GET 链接。

`@login_required` 让未登录访问者转到登录页。`LOGIN_URL` 配置了登录地址。Django session 保存登录状态，密码由 Django 进行哈希处理。

## 5. 技能帖创建、编辑和删除

`skill_create()`：验证表单后，`save(commit=False)` 先创建 Python 对象，再设置 `skill.owner = request.user`，最后保存数据库。

`skill_edit()`：`get_object_or_404(Skill, pk=pk, owner=request.user)` 同时按编号和当前用户筛选。别人即使手输编辑 URL，也拿不到帖子。

`skill_delete()`：GET 只展示确认页，POST 才执行删除。删除技能也会删除其评价，页面会提前说明。

`dashboard()`：从 `request.user.skills` 查询，只展示当前用户自己的帖。模板隐藏编辑按钮只是界面处理，真正的权限保护在视图查询中。

## 6. 搜索功能：逐步解释

### 第一步：提供 GET 搜索表单

打开 `templates/skills/skill_list.html`。`<form method="get">` 中有 `name="q"` 的搜索框和 `name="category"` 的分类框。例如搜索 Python 后，URL 是 `/?q=Python&category=`。GET 查询不会修改数据，地址可以收藏和分享。

### 第二步：在函数视图接收搜索词

```python
query = request.GET.get('q', '').strip()
category = request.GET.get('category', '').strip()
```

`request.GET` 读取 URL 参数，缺失时使用空字符串，`strip()` 去掉首尾空格。没有搜索词时显示所有技能。

### 第三步：使用 Q 对象搜索两个字段

```python
from django.db.models import Q

if query:
    skills = skills.filter(
        Q(title__icontains=query) | Q(category__icontains=query)
    )
```

`icontains` 表示不区分大小写的包含匹配（SQLite 对部分非 ASCII 字符的大小写处理有限）。`|` 是 OR：标题或分类匹配即可。分类在数据库中保存为如 `Technology`、`Design` 的英文值，因此搜索使用这些值；中文标题可按原文字面搜索。

ORM 将值作为查询参数处理，不需要也不应该把用户输入拼接成 SQL。查询结果按创建时间与编号倒序，分页顺序稳定。

### 第四步：叠加分类筛选

```python
if category:
    skills = skills.filter(category=category)
```

这里使用精确匹配。选择 Music 并搜索 Python 时，结果必须同时属于 Music 且符合搜索词。清空按钮返回首页，移除条件。

### 第五步：把结果传给模板

`Paginator(skills, 9)` 每页九条；`get_page()` 对无效页码作容错。`query` 和 `category` 一起传回模板，用于保留输入。翻页链接使用 `urlencode` 编码查询词并保留筛选参数。无结果时显示空状态，而不是空白页面。

手工验证：创建标题含 Python 的 Technology 帖；搜索 `python` 应找到它，搜索 `Technology` 也应找到它；搜索不存在的词应显示空状态。再选择不同分类，检查组合条件。

## 7. Bootstrap 样式：逐步解释

1. `base.html` 引入 Bootstrap CSS，再引入本地 `style.css`，后者负责覆盖配色和圆角。所有页面继承基础模板，所以导航和页脚只维护一份。
2. 使用 `container` 限制宽度，`row` 和 `col-lg-8` 等类进行响应式布局。列表使用 `row-cols-1 row-cols-md-2 row-cols-lg-3`：手机一列、中等屏幕两列、大屏三列。
3. `includes/skill_card.html` 是可复用技能卡片：分类、评分、标题、简介、位置、交换条件和详情按钮。
4. `static/css/style.css` 使用靛蓝主色、浅色渐变 hero、白色卡片、适度圆角和留白。修改这个文件即可换色，不必重写页面。
5. 页面使用真实 label、可见焦点样式、文本评分及表单错误提示；减少动态效果设置也得到尊重。导航使用自动换行，无需额外 JavaScript 或折叠菜单插件。
6. 空列表、无搜索结果、无评价都有明确提示和下一步按钮。浏览器缩小到手机宽度检查布局。

Bootstrap CSS 来自 CDN，离线时 Bootstrap 栅格与组件样式不可用。后续需要离线运行时，可将固定版本 Bootstrap CSS 下载到本地 static 并修改引用。

## 8. 评分与评价：逐步解释

1. 打开详情时读取现有评价。登录用户有自己的评价时，用它初始化 `ReviewForm`。
2. 提交时先检查登录状态，再禁止帖主自评。
3. 服务端固定 `skill` 和 `author`，以现有评价或新建评价对象初始化表单。
4. 验证通过后保存；已有评价是更新，不是新增第二条。
5. `Avg('rating')` 算术平均评分，模板保留一位小数。无评价时显示 “No ratings yet”。列表用 `annotate()` 一次查询附加平均分和评价条数。
6. 删除评价只接受 POST，并按 `author=request.user` 查找，因此只能删除自己的评价。
7. 用户文字默认经过 Django HTML 转义，描述与评论使用 `linebreaks` 展示换行，不能执行其中的脚本。

目前“Used this skill?” 是对用户诚实填写的提示，没有订单证明。若以后必须保证只有实际使用者可评价，应增加预约／订单与完成状态，再在提交评价时检查当前用户的已完成记录，而不只是改变按钮文字。

## 9. 路由与后台

| 地址 | 用途 |
| --- | --- |
| `/` | 浏览、搜索、分类、分页 |
| `/accounts/register/` | 注册 |
| `/accounts/login/` | 登录 |
| `/accounts/logout/` | POST 退出 |
| `/dashboard/` | 自己的帖子 |
| `/skills/new/` | 创建帖 |
| `/skills/<id>/` | 详情、提交／更新评价 |
| `/skills/<id>/edit/` | 编辑自己的帖 |
| `/skills/<id>/delete/` | 删除确认和 POST 删除 |
| `/reviews/<id>/delete/` | POST 删除自己的评价 |
| `/admin/` | 管理后台 |

`skills/admin.py` 注册两个模型，并设置列表字段、筛选条件和搜索字段。Django 自带用户管理已启用。先执行 `python manage.py createsuperuser` 创建自己的管理员账号。

## 10. 验证与下一步

执行 `python manage.py test`。测试涵盖注册登录退出、本地 next 跳转、公开浏览与搜索、分页、帖主权限、CRUD、评价增改删、评分约束、禁止自评、CSRF、文本转义与后台访问。

建议手工使用两个账号：A 发帖；B 搜索并评价；A 查看平均分；B 更新评价；确认 B 不能修改 A 的帖。最后使用 A 打开删除确认页，先取消，再确认删除。

未来可以添加头像、校园邮箱认证、聊天、收藏、预约和经过验证的评价。优先保持已有权限和数据库约束；新增字段后生成迁移，并为新规则增加测试。
